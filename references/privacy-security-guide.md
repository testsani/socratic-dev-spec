# 개인정보·보안 설계 가이드

## 개인정보·보안·학교 환경 확인

교육용 프로그램일 가능성이 있으므로 관련이 있을 때 다음 사항을 반드시 확인한다.

- 학생 이름
- 학번
- 연락처
- 성적
- 출결
- 상담 기록
- 사진과 영상
- 건강 정보
- 학부모 정보
- 미성년자 개인정보
- 외부 AI 서비스로 전송되는 정보
- 학교 또는 교육청의 보안 정책
- 자료 보관 기간
- 자료 삭제 방법
- 사용자별 접근 권한
- 관리자 접근 범위
- 백업과 복구
- 학교 내부망 사용 여부
- 공개 인터넷 서비스 여부

다음 원칙을 적용한다.

- 필요한 개인정보만 최소한으로 수집한다.
- 수집 목적이 분명하지 않은 정보는 저장하지 않도록 제안한다.
- 역할별로 필요한 정보만 열람하게 한다.
- 학생 개인정보를 개발용 예시나 로그에 그대로 넣지 않도록 한다.
- 실제 학생 정보 대신 가상 데이터로 시제품을 만들 수 있는지 확인한다.
- 비밀번호, API 키, 비밀값을 소스코드에 직접 작성하지 않도록 명세한다.
- 중요한 작업에는 입력 검증과 권한 확인을 요구한다.
- 개인정보가 로그, 오류 메시지 또는 URL에 노출되지 않도록 고려한다.
- 외부 AI 서비스로 전송되는 데이터와 그 필요성을 명확히 한다.
- 자료 삭제와 계정 삭제 시 처리 방식을 정한다.
- 백업 자료의 보관 및 삭제도 고려한다.

법률, 규정 또는 기관 정책을 확정적으로 단정하지 않는다.

확인이 필요한 법적·정책적 사항은 다음과 같이 표시한다.

- 확인이 필요한 사항
- 확인해야 할 담당자 또는 기관
- 확인 전에는 사용하지 말아야 할 기능
- 개인정보를 제외하고 시제품을 만드는 대안

이 스킬은 설계 단계의 개인정보·보안 검토를 지원하지만 다음을 대체하지 않는다고 명확히 한다.

- 법률 전문가 검토
- 학교 또는 교육청의 공식 보안 승인
- 실제 소스코드 보안 감사
- 클라우드 보안 설정 점검
- 모의해킹 또는 침투 테스트

보안 요구사항은 다음 세 단계로 구분한다.

1. 개발 전에 확인할 사항
2. 개발 중 구현할 사항
3. 배포 전에 검증할 사항

## 기록 형식과 단계별 확인

실제 개인정보를 보내 달라고 하지 말고 항목의 종류·필요성·대상 연령·처리 흐름을 질문한다. 외부 AI에는 무엇을 보내며 식별정보를 제외할 수 있는지, 결과를 누가 검토하고 오류를 어떻게 수정할지 확인한다. 허용 여부가 확인되지 않은 데이터 전송은 가상 데이터로 대체한다.

| 단계 | 확인·구현할 사항 | 근거·담당자 | 완료 증거·미결정 |
|---|---|---|---|
| 개발 전 | 최소 수집, 학생·미성년자, 목적, 기관 정책, 저장 위치, 외부 전송, 보관 기간 | 확인할 기관·담당자 기록 | 미확인 시 제한할 기능과 가상 데이터 대안 |
| 개발 중 | 서버 측 역할·자료 범위 검증, 입력 검증, 비밀값 분리, 세션, 로그·오류·URL 비식별 처리 | 관련 FR/NFR | 허용·거부 사례 테스트 |
| 배포 전 | 다른 학급·계정 자료 접근 차단, 전송·저장 보호 설정, 로그 노출, 백업·복구·삭제, 외부 서비스 설정 | 검증 담당자 | 실제 검증 결과 또는 검증 예정 |

역할별 조회·수정·삭제 범위를 학교·학급·소유자 단위로 정의한다. 숨긴 버튼만으로 권한을 구현하지 않는다. 계정 삭제 시 연결 데이터와 파일 처리, 백업 보관·접근·만료, 복구 시 삭제 자료가 다시 살아나지 않도록 할 방식을 기록한다.

시제품은 가상의 이름·학급·성적·연락처를 사용하며 실제 학생 자료를 가명만 바꾸어 복사하지 않는다. 법률 준수 판정, 공식 보안 승인, 소스코드 감사, 클라우드 설정 감사, 침투 테스트를 수행했다고 표현하지 않는다.
